# 安全模型与数据边界

本项目的安全目标是：能够把视觉配置部署到本机客户端，同时让“命令跑通”“窗口有回复”“真实图片被正确路由”“发布包不含密钥”保持可区分。控制平面只在用户授权的客户端目录写入受控配置；它不是杀毒软件，也不能替代客户端、模型服务或 Windows 账户的安全边界。

## 凭据处理

- 命令参数不接受明文 API key；子进程通过参数数组启动，避免 shell 拼接。
- 凭据优先从活动进程、用户/机器环境和适配器明确支持的客户端安全文件读取；不会遍历任意项目目录猜测密钥。
- 屏幕、stdout、stderr、JSON、收据、日志、诊断 ZIP、Git 差异和发布 ZIP 均不应出现密钥。诊断只记录“存在/缺失”、来源类别和不可逆短指纹。
- 写入 `.env` 或 Qwen-MM 配置时，事务先备份，原子替换后收紧 ACL；在 finally 中清理可清理的临时字节缓冲。
- 不要把凭据粘贴到 Hermes/DeepSeek Harness 对话，也不要把它写进 Skill、issue、截图、测试输出或命令历史。

## 写入和回滚

每次安装都经过发现、能力探测、备份、原子写入、配置检查、读回和收据提交。受控文件列入 receipt；中途失败会尝试恢复，只有所有恢复动作和哈希检查完成才会报告已验证回滚。Qwen-MM 是独立可选事务，不能用它的失败覆盖或回滚 Hermes 原生验收。

回滚时使用具体 receipt，不按“最新目录”猜测目标。receipt 损坏、路径越界、reparse point、哈希不一致或备份缺失会阻断操作，避免把未知文件当成备份恢复。

## 诊断和发行包

诊断导出只包含脱敏的状态、版本、错误码、受控文件哈希、收据摘要和依赖结果；源目录扫描一次，ZIP 解压后再扫描一次。包构建使用显式 allowlist、固定 ZIP entry 时间、路径分隔符归一化，并拒绝符号链接/junction/reparse point。

发行 ZIP 排除：`.env`、`.git`、backups、sessions、日志、历史规划、任务报告、生成的 dist、原始业务图片和本机绝对路径。发布前必须同时扫描源码、ZIP、哈希文件和提交历史；本仓库的攻击型密钥字符串只允许出现在不进入发行 ZIP 的测试夹具中。

## 付费和网络边界

默认 doctor、安装、静态 verify、模拟测试和 package 不启动真实视觉 API。加入 `-ConfirmPaidCalls` 才允许目标客户端进行真实图片验证；这不会购买额度，也不会绕过服务端权限。Qwen-MM 的固定源、Skill 和 MCP 可能需要联网，网络失败应当返回阻断或降级，并保留原生 Hermes 路径。

## 目标客户端隔离

Hermes 主模型、聊天历史、账号和工具集合不属于本项目的迁移内容。DeepSeek Harness 只对 manifest 列出的受控文件做版本门控，外部挂载只读审计。TRAE、WorkBuddy 和其他桌面客户端不在本发行包的自动写入范围内。

## 报告疑似泄露

如果发现日志、收据、ZIP、Git diff 或屏幕中出现凭据：

1. 立即停止分享并撤销/轮换凭据。
2. 保留错误码、时间、版本和文件类别，不要复制秘密值。
3. 用隔离环境重跑 package/diagnostics 扫描，并确认输出没有旧文件。
4. 向维护者报告“哪个类别、何时、是否已轮换、哪条命令”，不要附截图中的密钥或完整日志。
